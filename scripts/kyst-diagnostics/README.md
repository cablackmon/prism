# NOX-11625 fixed diagnostic session — pre-release review

This temporary integration delivers the selected10-second page rAF measurement and Calendar scroll/restoration into the authenticated board iframe. It neither evaluates arbitrary source nor forwards arbitrary commands, URLs or coordinates. **No merge, deployment, resident reload, bootstrap, input or live capture is authorized by this code.** MAIN NOX must release the exact source/image/agent/config pins after NOX-CLONE's focused review.

## Implemented boundary

The root layout includes AcceptanceEntry only when KYST_DIAGNOSTIC_ENABLED=1. The fixed API repeats the existing household session validation; direct operator calls additionally require the existing service token and no browser Origin. The existing proxy rewrites browser Origin to kyst-board.fly.dev, while the renderer body must identify kyst-wall-proxy.fly.dev. Neither cookie nor token is returned. Operator credentials remain in the approved local file and never enter the kiosk publisher. Production durable storage is `/app/data/nox11625-diagnostics` on the existing prism_data volume. Confirm writable ownership during release preflight; this packet does not authorize changing it.

`begin` creates one immutable mission session, maximum45minutes, bound to generated build/probe content hashes. One browser document claim binds its opaque cookie hash, exact origin/path, iframe status, random document ID and viewport/DPR/visualViewport scale. A temporary fixed-position challenge uses established NOX tokens and never changes layout/focus. The operator must compare that challenge in the authenticated native identity-frame, tied to a fresh verified kiosk PID/creation/session receipt, before `verify`. Merely knowing the challenge from collector status is insufficient evidence: **do not attest an unobserved native frame**. A second claimant or wrong challenge is refused, not rebound. The marker disappears after verification or entry termination. It may temporarily cover a small portion of the board; it is absent during measurement and final theme acceptance captures.

The persistent transaction lock has no stale takeover. State writes use atomic rename/fsync; an interrupted lock/write is a reconciliation failure, never permission to reset the session. Issued grants are permanently consumed. `publish` durably marks a native grant before SSH queue publication; lost HTTP/SSH responses, moved queue files or expired receipt history cannot authorize another publication. Only operator.py is the supported native dispatcher; queue-phase.ps1 is its internal, pinned publisher. No parallel retry ledger is added.

Measurement and scrolling are serialized. A scroll-owned screenshot grant is the sole allowed sub-operation. The capture acknowledgement must match that grant, native dimensions/hash/time and active window, and is service-token-authenticated. Operator.py validates the exact command receipt, downloaded bytes and native image dimensions before acknowledging. A60-second page timer restores the retained Calendar node if capture is missed; a suspended renderer can delay it. An outstanding native publication continues blocking later work after scroll termination. Both original and cleanup failures survive in terminal records, including exceptions from scrollTo. Terminal browser/native reports remain admissible after session expiry/disable; expiry prevents new effects. Zero trusted touch samples never imply a touch pass.

## Source/image and agent packet

`generate.mjs` embeds the literal probe without runtime eval and seals the changed runtime sources into generated-pins.json. Re-run it after any collector/client/probe/layout change. The release artifact's source commit and immutable image digest must map to these hashes; browser content hash is not by itself an OS process identity.

`install/agent.ps1` changes exactly one resident allowlist line to admit `nox11625-diagnostic-load`. All accepted capture/input/load bodies are unchanged. `install/diagnostic-operator.ps1` repins the approved handle-bound resident replacement/restore to baseline47f1322b and the new candidate. Backup, source, task, supervisor, owner/session, terminal-state and queue checks remain. New staging directory: `C:\NoxAgent\review\nox-11625-diagnostic-load`. Stage only exact manifest bytes after release, refuse differing existing bytes. Review the reload and rollback pins together. No service/task/profile/flag edits or alternate process launch.

The named diagnostic load uses the existing bounded board task mechanics: verify the exact current kiosk task/root and no unrelated Edge; stop only the handle-bound verified board process, wait for terminal state, then start the **existing task unchanged once**. It therefore replaces the board document/process while retaining the existing profile, task URL and saved settings. It is not a page-only HTTP refresh. The native `nox11625-diagnostic-load.claimed` and server issuance both persist. No startup click is added. Prompt, Night Sky, changed target or ambiguous completion means stop. Existing startup/Dismiss/observation claims are never reset or repurposed.
